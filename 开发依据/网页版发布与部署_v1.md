## 费用

本机开发、测试和构建不需要购买云服务。长期给中国大陆学生使用通常需要域名和可持久保存资料的云服务器或托管服务，供应商按套餐收费；实际价格与地区、容量、流量和学生人数有关。域名备案本身通常不收费，但需要符合所选服务商与地区的实名和备案条件。学生连接自己的模型 API 时，模型费用由该服务商按其规则收取。免费海外试用地址不适合作为面向中国大陆学生的稳定正式网址。

## 获取正式网址后的部署

1. 注册并持有域名、可运行 Docker 的云服务器，将域名解析到服务器。确认服务器能使用 80 和 443 端口，并完成适用的备案与发布主体手续。SSH 端口仅允许管理员地址访问；不要公开应用的 4174 端口。
2. 将项目放到服务器，复制 `.env.production.example` 为 `.env.production`，把 `YINGXING_DOMAIN` 改成实际域名。不要把任何账号密码或学生密钥写到配置文件。
3. 执行 `docker compose --env-file .env.production up -d --build`。`yingxing_data` 命名卷保存学生资料和账号数据库，重建容器不会删除该卷。
4. 执行 `docker compose --env-file .env.production ps` 检查 `app` 为 healthy、`web` 为 running，然后在两台不同设备打开 `https://实际域名/`，分别注册测试账号并完成导入、笔记保存、退出、重新登录及跨账号访问测试。
5. 为服务器和数据库建立自动备份及恢复演练。每名学生可在“账号”中下载自己的资料备份 ZIP；这不替代服务器侧整站备份。更新前必须先做整站备份。

## 安全与运营边界

- 公开模式必须设置 `YINGXING_PUBLIC=1` 和 `YINGXING_PUBLIC_ORIGIN=https://实际域名`。HTTP 只允许通过显式测试开关在本机使用。服务默认只监听本机；容器模式通过 `YINGXING_BIND_HOST=0.0.0.0` 供同一 Compose 网络中的 Caddy 访问，应用端口没有发布到公网。Compose 同时开启可信代理地址识别，Caddy 覆盖传入的转发地址头；应用据此按访客地址限制登录和注册尝试次数。
- 学生密码不以明文保存；会话 Cookie 仅服务器可读、跨站受限。模型密钥在当前浏览器按账号分别加密保存，不写入学生资料 ZIP；更换浏览器需重新配置模型。公开模式限制模型接口为公网 HTTPS 地址，并禁止重定向。
- 当前注册无需邮箱验证；没有邮件找回，学生必须保存注册时显示的恢复码。没有实现跨设备同步冲突处理、细粒度配额、反滥用验证码、管理员封禁、自动备份、监控告警或大规模并发压测。上线为不受限的公开服务前，需要补齐这些运营能力，并对文件上传、模型服务转发和数据删除做独立安全审查。
- 用户当前没有发布主体、域名和云服务器，隐私政策、用户协议、客服联系信息、目标年龄范围等对外页面资料也未确定。这些不能代填或代注册。
