# 源笔记多平台发布准备 v1

更新：2026-11-16。目标为多名学生分别使用的公开网页版，以及 Windows、Android、iOS 应用。此文件记录实际项目状态与待办，不代表已通过应用商店审核。

## 当前已具备

1. 本机网页版可运行；生产构建由 Express 提供前端和 API，默认只监听 `127.0.0.1:4174`。另有独立的公开模式，已在本机验证两账号隔离，但尚无公网部署。
2. 已添加网页应用清单、192/512 像素图标、iOS 主屏幕图标与离线连接提示。普通网页版仍须连接服务；另有独立 Android 离线测试版，PDF 和笔记保存在手机本地，智能生成需联网访问用户配置的模型接口。
3. PDF、PPT、Word 预览依赖 Poppler、LibreOffice；Windows 上的 Word 转换还会优先尝试本机 Microsoft Word。模型由用户自行提供 API 密钥。
4. 默认本机模式的 `data/` 保存单一资料库。公开模式增加账号、会话和各用户独立的资料目录；模型配置与加密后的密钥按账号保存在当前浏览器。公开模式尚缺细粒度配额、邮件验证及运营级反滥用能力。

**结论：当前可供单人在本机使用和安装网页外壳；多用户公开模式已在本机测试，仍需域名、服务器和线上验收才能获得公开网址；另有未签名的 Windows x64 预览安装包和已签名的 Android 离线测试 APK。尚无可提交商店的 Windows/MSIX、Android/AAB、iOS/IPA。** 不能将默认本机模式的端口转发到公网作为上线替代方案。

## 发布顺序

### 1. 多用户网页版

- 增加注册、登录、邮箱验证、找回密码、退出及账号删除；每一个 API 请求都要有服务端验证的用户身份。
- 将文档、笔记、批注、图片、模板和备份按用户隔离，文件下载也必须校验归属。用数据库管理账号与索引，文件放在按用户授权的持久存储中。现有 `data/` 不能直接当成所有学生的共用资料库。
- 给上传、文档转换和 AI 请求设置容量、时长、并发与费用限制；处理异常文件、服务商错误和重复提交。模型密钥不能进入应用包、日志或公开接口；明确在设备与云端如何保存和使用。
- 采用 HTTPS、会话保护、备份与恢复、监控和版本迁移。上线前做跨账号访问、越权下载、并发写入、异常上传、数据删除/导出的端到端测试。
- 准备隐私政策、用户协议、联系渠道和内容删除流程。若在中国大陆服务器公开提供服务，还需核对域名备案、适用的互联网服务与个人信息要求。
- 确定域名、云服务器或托管平台、数据库和对象存储后，部署测试环境，再用独立学生账号完成真实设备验收，最后发布正式网址。

### 2. Windows

- 已制作 `release/源笔记 Setup 0.1.0.exe` 预览安装包。Electron 启动独立本机服务，资料写入应用用户数据目录；每次启动复用本机端口，以保留浏览器中加密保存的模型配置和其他偏好。旧名称版本曾在本机测试安装、启动、PDF/PPTX/DOCX 样例导入、原文显示、笔记保存、重启及卸载；本次改名后的安装包已通过构建及产品名称检查，尚未重新执行完整安装流程。
- 该包未签名，没有内置 LibreOffice 和 Poppler，也未在没有开发工具的干净电脑上测试，因此仅用于本机预览，不是商店提交物。正式包的应用标识和发布主体也尚未确定。
- 在网页版账号与在线存储可用后，封装同一套前端与 API；决定是以在线客户端为主，还是维护本机离线资料库和同步。两种模式的数据迁移、冲突处理与备份不同。
- 若提供 Windows 独立安装包，应确定文档转换工具如何随包合法分发或明确安装前提；制作安装、卸载、升级和签名流程，并在一台没有开发环境的干净电脑上测试。
- Microsoft Store 需要开发者账号、应用标识、展示资料、隐私政策及合规安装包。直接安装包与 Microsoft Store 是两个发布渠道。

### 3. Android

- 已制作 `release/源笔记-Android-离线测试版.apk`。应用内置网页资源，资料和笔记存于手机本地；断网可继续阅读与编辑，智能生成需联网访问用户自行配置的 HTTPS 模型接口。原生文件选择、下载、手写触控、键盘遮挡及后台恢复仍需真机验证。公开网页版是独立发布任务。
- Google Play 通常提交签名的 AAB；其他 Android 商店（例如华为、小米、OPPO、vivo）各自要求开发者账号、签名、隐私信息、截图与审核材料，具体格式和当前政策以各平台后台为准。
- 用至少一台普通手机和一台大屏/手写平板测试导入、预览、编辑、跨页跳转、模型连接、重启恢复和升级。浏览器尺寸模拟不能替代触控与文件授权测试。

### 4. iOS / iPadOS

- iPhone/iPad 可先通过 Safari“添加到主屏幕”使用公开网页版；这不会自动进入 App Store。
- App Store 版需要 Apple Developer 账号、可运行 Xcode 的 macOS 环境、签名、TestFlight、隐私信息、截图和审核。可复用网页前端，但文件导入、Apple Pencil、键盘、下载、会话恢复须按 iOS 设备单独验收。
- 仅包裹一个网页可能不满足 App Store 对应用体验的要求；应提供可靠的原生文件工作流和适合设备的编辑体验后再提交。

## 申请与提供的信息

用户目前没有域名、云服务器或开发者账号。正式发布前需由发布者自行注册并持有：域名及 HTTPS 托管资源、Microsoft/Google/Apple 开发者账号，以及计划覆盖的国内 Android 商店账号；iOS 构建还需要 macOS。无需向开发人员发送任何账号密码、验证码、API 密钥或签名私钥。

需要确定应用的发布主体（个人或公司）、公开名称、客服/支持联系方式、隐私政策地址、服务地区、年龄范围、计费方式，以及是否允许未成年人注册。这些信息决定商店资料和用户数据处理方式，不能凭空代填。
