# 项目结构与开发

源笔记当前应用版本为 0.3.0，Android 包版本为 0.4.0-offline。面向使用者的入口见[首页](../README.md)，本页面向需要运行源码或参与开发的人。

## 技术组成

| 部分 | 当前实现 |
| --- | --- |
| 界面 | React 19、Vite、Lucide 图标 |
| 正文编辑 | Tiptap，文字/公式/图片混合编辑 |
| 数学输入与展示 | MathLive、KaTeX |
| PDF 阅读 | PDF.js，配套字体、CMap、WASM 等资源位于 `public/pdfjs/` |
| 本机/服务器后端 | Node.js 24+、Express，文件处理和资料保存 |
| 文档工具 | Poppler；Word/PPT 转换使用 LibreOffice，Windows Word 可使用 Microsoft Word |
| Windows 客户端 | Electron，NSIS 安装包 |
| Android 客户端 | 原生 Android 工程、WebView、本地存储和联网/下载桥 |
| AI | 用户自带 Chat Completions 兼容接口；具名工具执行与确认 |

Android 离线包直接使用设备内的网页资源和存储，不依赖手机连接电脑服务。公开网页模式与单机模式使用不同的账号和存储方式。

## 启动

准备 Git、Node.js 24+ 和 npm。首次安装依赖需要访问相应软件源。PDF 功能还需 Poppler，Office 转换需相应工具。

```powershell
git clone https://github.com/kaituozher11-png/yuan-notes.git
cd yuan-notes
npm ci
npm run build
npm start
```

同机访问 <http://127.0.0.1:4174/>。开发界面使用 `npm run dev`，打开 <http://127.0.0.1:5173/>；Vite 会把 API 请求转到 4174。关闭服务后普通网页版不可用。

| 命令 | 用途 |
| --- | --- |
| `npm run dev` | 同时启动 API 和 Vite 开发界面 |
| `npm test` | 执行 `tests/*.test.js` 的 Node 自动测试 |
| `npm run build` | 构建网页到 `dist/` |
| `npm start` | 启动后端并提供已构建页面 |
| `npm run desktop:dev` | 启动 Electron 开发客户端，先准备网页构建 |
| `npm run desktop:pack` | 在 Windows 构建并生成可执行目录 |
| `npm run desktop:installer` | 在 Windows 构建并生成 NSIS 安装包 |

## 运行路径与工具

本机服务默认使用项目内 `data/`，可用 `YINGXING_DATA_DIR` 指定资料目录。不要让测试服务和正式资料库同时写入同一个目录。切换资料路径前先备份。

Poppler 可加入系统 `Path`，也可通过 `YINGXING_PDFINFO_PATH`、`YINGXING_PDFTOTEXT_PATH`、`YINGXING_PDFTOPPM_PATH` 指定对应可执行文件。LibreOffice 路径可通过 `LIBREOFFICE_PATH` 指定。普通安装版用户参考[图文配置步骤](使用指南.md#windows-安装与工具配置)。

## Android 打包

需要 JDK 21、Android SDK（compileSdk 35）、可用的 Gradle 8.11.1，并设置自己的 `JAVA_HOME`、`ANDROID_HOME`。仓库没有随附 Gradle Wrapper，不能直接假定有 `gradlew`。

```powershell
npm ci
npm run build
gradle -p android assembleDebug
```

这里的 `gradle` 需事先安装或换成实际可执行路径。首次构建需要获取依赖，只有依赖完整缓存时才适合追加 `--offline`。工程的 `syncOfflineWeb` 会将 `dist/` 嵌入 APK，产物为 `android/app/build/outputs/apk/debug/app-debug.apk`。

自己构建的 Debug APK 默认使用自己电脑的测试签名，通常不能直接覆盖本项目已发布的测试 APK。原发布签名不包含在仓库；不要因此卸载唯一含资料的旧版。
