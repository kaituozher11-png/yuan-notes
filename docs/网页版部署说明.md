# 网页版与自行部署说明

本页说明当前代码的本机网页和公开模式，**不是官方在线服务地址**。项目目前没有已经开放的公共网址。普通用户优先使用[安装包](../README.md#下载与安装)。

## 三种使用方式

| 方式 | 资料在哪里 | 是否需要账号 | 适合场景 |
| --- | --- | --- | --- |
| 本机源码网页 | 自己电脑的资料目录 | 默认本机模式无需注册 | 自己在浏览器阅读和记笔记 |
| Windows / Android 安装版 | 各自设备本地 | 默认无需注册 | 直接安装使用，Android 无需连接电脑 |
| 自建公开网页 | 自己服务器按账号存储 | 公开模式注册/登录 | 由有部署经验的人维护多人服务 |

`127.0.0.1` 仅代表访问者当前设备。普通网页依赖服务，不支持只上传 `dist/` 到静态空间。单机客户端与自建服务器不自动同步；同一服务器账号也不提供实时协作或同时编辑的冲突合并。

## 本机启动

按[源码运行步骤](../README.md#从源码运行网页版)安装依赖和文档工具，运行 `npm run build`、`npm start`，同机访问 <http://127.0.0.1:4174/>。默认只监听本机，不应把无账号模式直接映射到公网。

## 公开模式已具备的功能

- 注册、登录、退出，以一次性恢复码重置密码。
- 按用户隔离资料、笔记、图片、模板和备份；账号相关数据在服务器保存。
- 账号与资料删除入口；模型设置在当前浏览器按账号保存，不包含在资料备份中。
- 公开模式的来源检查、HTTPS 要求和模型目标地址限制。

注册不带邮箱验证或邮件找回，请保存恢复码。源码存在这些能力不等于已有可用的官方服务。

## 自建服务的准备与配置

需要自行准备 Node.js 24+ 运行环境、文档转换工具、持久存储、域名、有效 HTTPS 及反向代理。模型请求还需服务器能够访问用户选择的服务商；服务器、域名和模型调用可能产生相应费用。

使用完整源码构建后，公开模式核心环境变量示例如下。域名和目录必须换成自己实际拥有和管理的值；示例并不是可直接访问的网址。

```bash
export YINGXING_PUBLIC=1
export YINGXING_PUBLIC_ORIGIN=https://notes.example.com
export YINGXING_BIND_HOST=127.0.0.1
export PORT=4174
export YINGXING_DATA_DIR=/srv/yuan-notes-data
export YINGXING_TRUST_PROXY=1
npm start
```

以上示例对应“同机 HTTPS 反向代理 → 本机 Node 服务”。`YINGXING_TRUST_PROXY=1` 仅用于可信代理配置，代理需正确处理转发头；容器网络等其他拓扑需单独检查监听和代理配置。不要把密码或密钥写进公开仓库。请自行配置进程守护、可写数据目录、服务器备份与恢复，并按所在地要求办理对外发布手续。

上线前至少在两独立账号下验证导入、阅读、笔记保存、退出重登、跨账号不可访问、模型请求、备份和重启后持久化。没有单纯通过修改一个端口就完成正式上线的步骤。

## 现有 Docker 文件的状态

仓库保留 `Dockerfile`、`compose.yaml`、`Caddyfile` 和旧部署记录，**目前不能把它们视为已与最新源码同步的一键部署方案**。本次文档检查发现，现有 Dockerfile 构建阶段没有复制 Vite 现在需要的 `offline.html`，运行阶段也没有复制后端引用的 `src/` 共享模块；需要先补齐并重新验证镜像构建和容器运行。

本次只更新项目说明，没有修改部署代码，也没有重新进行容器或公网部署测试。此前记录的容器验收属于旧版本，不可据此认定当前 Docker 构建可用。[旧部署记录](../开发依据/网页版发布与部署_v1.md)仅作为历史实现参考，不建议直接照其中旧命令上线最新版本。

## 当前服务边界

当前没有完整的服务运营体系：尚未提供细粒度配额、验证码、邮件找回、管理员封禁、自动整站备份、监控告警或大规模并发验证。公开服务的隐私说明、联系方式、资料处理规则和维护责任需由实际运营者准备。

多用户模式不代表无限量文件存储或不限成本的模型代理。对不受限的公网使用，应先评估实际容量、外部接口费用和上传处理开销，并完成对应运行和权限检查。
